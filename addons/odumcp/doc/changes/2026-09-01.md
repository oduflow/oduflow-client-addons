# 2026-09-01

## Change plans are grouped by the request they came from

- A connector task that touches a hundred records used to produce a hundred
  separate plans in **OduMCP > Approval Inbox**, with nothing tying them
  together. Every plan now carries a **Request** reference such as
  `MCP/2026/00042`, and the inbox is grouped by it by default.
- The MCP client can send a **batch key** with every preview of one task, and
  all those plans land in the same request. Without a batch key Odoo groups the
  plans of one connector user and profile that arrive close together, so a
  single task still ends up as a single request.
- **Settings > OduMCP > Approvals** carries the new **Request Grouping
  Window (minutes)** (default 10). It only affects plans that arrive without a
  batch key; zero puts every plan in its own request.
- Plans that existed before the upgrade are grouped by the same rule, so the
  inbox does not start with one nameless group.

## Approving a whole request takes one step

- The header buttons of the Approval Inbox are now **Approve Selected**,
  **Reject Selected** and **Delete Selected Expired**, and the confirmation
  dialog shows the request of every plan it will process. Open a request, tick
  the header checkbox, and the whole group is decided at once — approving only
  part of a request stays possible.
- Nothing changes about what an approval means: plans stay immutable, an
  approved plan is still executed once by the client, and a plan whose state no
  longer fits the action is skipped and reported instead of being forced.
