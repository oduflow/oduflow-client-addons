# 2026-08-28

## Rejected connector calls now say what to fix

- A field name that does not exist on the model is reported as `unknown_field`
  instead of `field_denied`. A typo or a field borrowed from another Odoo
  version no longer looks like a permission problem.
- `field_denied`, `unknown_field` and `access_denied` now name the offending
  fields or record ids in the error, so a rejected call can be repaired in one
  step instead of by trial and error.
- A record id that no longer exists is reported as `record_not_found`, while an
  existing record outside the profile scope remains `access_denied`. A mixed
  request lists both missing and denied ids in one error.
- The connector tool descriptions now state that field names come from the model
  description and that a single bad name or id rejects the whole call.

## Optional partial reads instead of a refused call

- A new profile capability, **Partial Field Reads**, answers a read with the
  readable columns and an `omitted_fields` note instead of refusing it. It is
  off by default, so existing profiles keep refusing such calls.
- Trimming applies only to a plain field list. A withheld field in a search
  domain or in the sort order still fails, a write is never trimmed, and a read
  whose fields are all withheld still fails rather than returning an empty
  success.
- The audit row of a partial read records the skipped field names.

## Publishing the sidecar image

- `addons/odumcp/deploy/publish.sh` builds the sidecar and pushes it
  to Docker Hub under both its `pyproject.toml` version and `latest`, running
  the test suite first and refusing to overwrite an already published version.
  A missing test runner or an inconclusive registry check now stops publication
  instead of silently skipping the safeguard.
