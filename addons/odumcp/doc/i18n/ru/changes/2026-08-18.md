# 2026-08-18

## Зачем MCP Active рядом с Profile

- В руководстве администратора теперь объяснены оба поля: профиль говорит, что
  пользователю можно делать, а галочка — можно ли ему вообще что-нибудь.
- Галочка остаётся снятой, пока её не включат вручную, поэтому профиль,
  пришедший из шаблона пользователя, сам по себе ничего не даёт.
- Снятая галочка при сохранённом профиле описана как штатный способ
  приостановить одного человека вместо очистки профиля или архивации
  пользователя.

## Как читать отказ в MCP-запросе

- Новый раздел описывает, что видит получивший отказ: `403` с
  `mcp_access_not_configured`, если профиль не выбран, и `inactive_mcp_access`,
  если неактивны пользователь, галочка или профиль.
- MCP-сервер отдаёт оба случая как `401`, поэтому клиент вообще не показывает
  инструмент Odoo, и сбой выглядит как отсутствующий сервер, а не как отказ
  пользователю.

## MCP-ключ следует за доступом

- Включение **MCP Active** пользователю теперь выпускает API-ключ только для
  MCP с именем **MCP access** и выбирает его ключом по умолчанию для OduPilot,
  поэтому пользователю чата больше не нужно заводить ключ вручную, прежде чем
  появится инструмент Odoo.
- Снятие галочки этот ключ удаляет. Ключи, созданные пользователем лично,
  остаются: снятая галочка их и так не принимает.
- Удаление пользователя со вкладки **Users** профиля теперь снимает и галочку —
  раньше такое сохранение вообще не проходило.
- Пользователям с уже включённой галочкой ключ выдаётся при обновлении модуля.

## Планы изменений показываются подсвеченным YAML

- **Redacted Diff** и **Result** в Approval Inbox теперь показывают сохранённый
  снимок подсвеченным YAML вместо одной строки сырого JSON.
- На **Integrity** MCP-менеджерам дополнительно виден отправленный payload,
  обезличенные значения выделены красным.
- В форме Audit Log затронутые записи собраны в блоке **Target Records** — тоже
  в виде YAML.
- Исходный JSON каждого блока остаётся доступным в режиме разработчика.

## Руководства описывают все возможности профиля

- Руководство пользователя перечисляет, что коннектор реально умеет, объясняет
  цикл предпросмотр → одобрение → исполнение, ключи идемпотентности, истечение
  плана, живые обновления ресурсов и ключи MCP, которые видит пользователь, а
  также покрывает больше кодов ошибок.
- Руководство администратора описывает лимиты профиля, резервный режим Default
  Model Access с его защитными списками запретов, каждый переключатель
  возможностей, Model Policies, Allowed Methods, содержимое аудита, хранение и
  глобальные настройки.
- **Activities** описан таким, какой он есть: разрешение *ставить* активность
  на доступную на запись запись, а не CRUD по `mail.activity`.
- **Auto Approve Low Risk** описан как применимый только к сообщениям в чаттере
  и постановке активностей и только к шагу ручного одобрения.
