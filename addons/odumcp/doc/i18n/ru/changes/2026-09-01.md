# 2026-09-01

## Планы изменений группируются по запросу, из которого пришли

- Задача коннектора на сто записей до сих пор порождала сто отдельных планов в
  **OduMCP > Approval Inbox**, и ничто их не связывало. Теперь каждый план
  несёт обозначение **Request** вида `MCP/2026/00042`, а инбокс по умолчанию
  сгруппирован по нему.
- MCP-клиент может отправлять **ключ партии** с каждым предпросмотром одной
  задачи, и все эти планы попадают в один запрос. Без ключа партии Odoo
  группирует планы одного пользователя коннектора и профиля, приходящие близко
  по времени, поэтому одна задача всё равно остаётся одним запросом.
- В **Settings > OduMCP > Approvals** появилось **Request Grouping Window
  (minutes)** (по умолчанию 10). Оно влияет только на планы, пришедшие без ключа
  партии; ноль помещает каждый план в собственный запрос.
- Планы, существовавшие до обновления, разложены по тому же правилу, поэтому
  инбокс не начинается с одной безымянной группы.

## Одобрение всего запроса — один шаг

- Кнопки шапки инбокса теперь называются **Approve Selected**, **Reject
  Selected** и **Delete Selected Expired**, а окно подтверждения показывает
  запрос каждого плана, который будет обработан. Откройте запрос, поставьте
  флажок в шапке — и вся группа решается разом; одобрить только часть запроса
  по-прежнему можно.
- Смысл одобрения не меняется: планы остаются неизменяемыми, одобренный план
  по-прежнему исполняется клиентом ровно один раз, а план, состояние которого не
  подходит действию, пропускается и попадает в отчёт, а не выполняется силой.
