# 2026-08-18

## Dlaczego MCP Aktywne istnieje obok profilu

- Przewodnik administratora wyjaśnia teraz dwa pola: profil określa, co może zrobić użytkownik, flaga określa, czy może on w ogóle coś zrobić.
- Flaga pozostaje wyłączona, dopóki nie zostanie włączona ręcznie, więc profil, który pochodzi z szablonu użytkownika nie daje nic na własną rękę.
- Usuwanie flagi podczas przechowywania profilu jest udokumentowane jako obsługiwany sposób zawieszenia jednej osoby, zamiast wyczyszczenia profilu lub archiwizacji użytkownika.

## Czytanie odrzuconego wniosku MCP

- Nowa sekcja opisuje to, co widzi odmówiony dzwoniący: `403` z `mcp_access_not_configured`, gdy nie jest wybrany profil i `inactive_mcp_access`, gdy użytkownik, flaga lub profil jest nieaktywny.
- Serwer MCP zgłasza zarówno jako `401`, więc klient nie oferuje żadnego narzędzia Odoo, a awaria wygląda raczej jak brakujący serwer niż odmówiony użytkownik.

## Klucz MCP następuje po dostępie

- Włączenie **MCP Aktywne** dla użytkownika teraz wydaje MCP- tylko klucz API o nazwie **Dostęp do MCP** i wybiera go jako OduPilot domyślnie, więc użytkownik czatu nie musi już tworzyć jeden ręcznie, zanim pojawi się narzędzie Odoo.
- Oczyszczenie flagi ponownie usuwa ten klucz. Klucze stworzone przez użytkownika osobiście są przechowywane, ponieważ oczyszczona flaga już je odmawia.
- Usunięcie użytkownika z zakładki **Użytkownicy** profilu teraz usuwa flagę, która wcześniej w ogóle nie chciała zapisać.
- Istniejący użytkownicy z włączoną flagą otrzymują klucz do aktualizacji.

## Plany zmian są pokazane jako zaznaczone JAML

- **Zredagowane różnicowanie** i **Wynik** w polu Aprobata teraz renderować zapisane migawki jak zaznaczone JAML zamiast jednej linii surowego JSON.
- **Integralność** dodatkowo pokazuje dostarczony ładunek dla menedżerów MCP, z zredagowanymi wartościami oznaczonymi na czerwono.
- Audyt Format dziennika pokazuje dotknięte id w bloku **Zapisy docelowe**, również jako YAML.
- Surowy JSON każdego bloku pozostaje dostępny w trybie deweloperskim.

## Przewodniki opisują teraz każdą zdolność profilu

- Przewodnik użytkownika wymienia, co może zrobić złącze, wyjaśnia podgląd / zatwierdzanie / wykonywanie podróży w obie strony, klucze idepotencji, wygaśnięcie planu, aktualizacje zasobów na żywo oraz klucze MCP, które użytkownik widzi i obejmuje więcej kodów błędów.
- Domyślny Model Access wraz z listami identyfikacyjnymi, wszystkimi przełącznikami funkcji, Modelową Polityką, Dozwolone Metody, Audyt treści, Retencja i Ustawienia globalne.
- **Działania** jest udokumentowany jako co to jest: pozwolenie na * harmonogram * aktywność na rekordzie zapisywalnym, a nie CRUD w `mail.activity`.
- **Automatyczne zatwierdzanie niskiego ryzyka** jest udokumentowany jako mający zastosowanie tylko do komunikatów i zaplanowanych działań oraz tylko do ręcznego etapu zatwierdzania.
