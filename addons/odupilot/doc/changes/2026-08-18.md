# 2026-08-18

## New chat opens with the cursor in the message box

- **New OduPilot** now switches Discuss to the freshly created conversation and
  focuses the message box, so the first message can be typed immediately.
- Previously the chat only appeared in the sidebar while the previously opened
  conversation stayed on screen, and it had to be clicked before typing. The
  second and every later chat created without reloading the page were affected.

## One retry notice per reason

- A provider that keeps retrying the same request now posts a single
  notification for as long as the reason stays the same.
- Reasons such as an exhausted plan limit carry a moment of reset and a
  remaining number of seconds that change with every attempt. Those numbers used
  to count as a new reason, so one waiting turn filled the conversation with
  identical notices.

## Discuss access is required for a chat

- The administrator guide now states that an assigned AI chat profile is not
  enough on its own: the user also needs the **Show Discuss** group, because
  **New OduPilot** sits below the Discuss root menu.

## Odoo tools need an MCP access profile

- The administrator guide now explains that the personal MCP key only
  identifies the caller. Reaching Odoo data also requires **MCP Active** and an
  MCP **Profile** on the same user.
- Without them the chat answers that no Odoo tool is available, which looks like
  a missing MCP server while the server is in fact refusing the user.

## Deleting a profile deletes its chats

- An AI chat profile can now be deleted while sessions or users still reference
  it. Its chats are deleted with it, their workspace directories are cleaned up
  on the bridge and their temporary MCP API keys are revoked.
- Assigned users, active and archived alike, simply lose the assignment and
  cannot start a chat until another profile is assigned.
- The Discuss conversations are kept and stay readable as ordinary channels.
- Deletion used to be refused outright as long as a single chat or user pointed
  at the profile.

## The last runtime error tells whether it is over

- The **Last Runtime Error** block on **Settings → OduPilot → Monitoring** now
  carries a badge: a green **Resolved · was 13 h ago** while the bridge no
  longer reports that failure, a red **Active · last seen 20 s ago** as long as
  it keeps arriving.
- The block never clears, so it used to sit under a healthy runtime with nothing
  but a timestamp to say whether the problem was still going on.

## No manual key before the first chat

- A user who is given MCP access now receives the MCP identity key with it, so
  the Odoo tool works in a chat without a visit to **Preferences > Account
  Security**.
- Choosing a personal key with **Use for OduPilot** still overrides the issued
  one for new sessions.

## The answer notification waits for you

- When an AI answer arrives while you are elsewhere in Odoo or in another
  conversation, the notification now stays on screen until you dismiss it and
  offers **Open chat**, which switches to that conversation with the cursor
  already in the message box.
- The notification used to close after a few seconds, so an answer to a request
  that took minutes could be missed entirely: AI conversations are not shown as
  docked chat windows, and nothing else announced them outside Discuss.
- A newer answer in the same chat replaces the previous notification, and
  opening the chat removes it.

## Reasoning and tool calls are visible in the conversation

- An answer now shows what happened on the way to it: **AI reasoning** and one
  **Tool call** heading per call, with its arguments and its result. Both are
  collapsed and expand on click; the answer itself stays expanded.
- AI writes an answer in several steps, and a step that only reasoned or only
  called a tool used to be dropped from the conversation entirely — it appeared
  in the live preview for a fraction of a second and was gone. Those steps are
  now stored as ordinary messages.
- During a turn the live preview keeps the earlier steps on screen until the
  answer is stored instead of clearing them at every step.

## Chat with AI in a docked window

- An AI conversation can now be held in the small window docked at the bottom of
  the screen, opened from the messaging icon, while you work in another Odoo
  application. The status bar, the live answer preview, reasoning and tool calls
  and permission cards are all there; the window folds and is restored after a
  page reload like any other conversation.
- AI conversations used to be pushed back into Discuss: clicking one in the
  messaging menu left the current screen, and a docked window closed itself.
- **New OduPilot** still opens the new conversation in Discuss. Developer chats
  stay full screen as well — their build logs, diffs and permission cards do not
  read in a narrow window.
- The answer notification is no longer shown when the chat is already in front
  of you in an unfolded docked window, and **Open chat** now opens the
  conversation without leaving your current screen.

## Ask AI from any record

- The chatter of every record now has an **Ask AI** button next to **Log note**.
  Write a question, and both the question and the AI answer are logged as
  internal notes on that record.
- Asking used to mean switching to Discuss, opening a chat and describing which
  record was meant; the answer stayed in that conversation and left no trace on
  the record.
- All chatter questions of one user share a single **Ask AI — <user>**
  conversation, which is created on the first question and does not count
  against the number of chats the user may open. Questions are answered one
  after another.
- Only the answer is written into the record. Reasoning and tool calls stay in
  the conversation, and a failed request is reported as a note as well.

## Only the answer raises a notification

- The reasoning and tool steps that AI posts while working no longer produce
  their own notification; one turn ends with one notification about the answer.
- Those steps arrive as ordinary bot messages, so every one of them used to
  replace the notification with an intermediate line such as a tool call, and
  the answer itself was just one more of them.

## AI conversations have their own sidebar section

- Discuss now lists AI conversations in a separate **AI** section above
  **Direct Messages**. It folds and unfolds on its own and remembers the state
  between visits.
- Existing AI conversations were moved into the section, closed ones included,
  and every new chat is created there.
- AI chats used to be mixed with personal conversations, which made them hard
  to find once a few of them were open.
