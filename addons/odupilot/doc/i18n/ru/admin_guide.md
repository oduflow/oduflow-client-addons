# Руководство администратора OduPilot

## Установка на Odoo 17

Установите `odupilot` из каталога `addons` этого репозитория. Зависимости включают `mail`, `auth_totp` и `odumcp`. Перед загрузкой модуля установите Python-пакеты из `.oduflow/requirements.txt`. Модули Odoo 15 `ai_chat`, `streams` и `bus_actions` не нужны.

Это порт для установки на Odoo 17. Он не переносит существующую базу Odoo 15 и не переименовывает установленные записи базы. Импортированные записи об изменениях описывают историю исходного модуля.

## Инфраструктура

Соберите и разверните `addons/odupilot/deploy/docker-compose.yml`. Скопируйте его `.env.example` в хранилище секретов и задайте учётные данные Odoo, OpenCode Basic Auth, имена томов и числовые UID/GID. OpenCode и мост используют частную сеть и постоянный том `/workspace`. Odoo хранит пути и конфигурацию; монтировать этот том ему не обязательно. Порт OpenCode `4096` должен оставаться закрытым извне.

Файл compose собирает локальный мост и закреплённый образ OpenCode. Он включает локальное преобразование документов через AnyDoc. Наличие переименованного образа в реестре не требуется. Сборка образов, подготовка рабочих папок и проверки запуска описаны в README развёртывания. Профилям разработчика дополнительно нужны учётные данные Git и настроенные инструменты окружения Oduflow.

Мост входит в Odoo отдельным внутренним пользователем с группой **OduPilot Bridge Service**. Назначьте её через технические настройки пользователей и групп. Она открывает служебные RPC-методы, возвращающие учётные данные развёртывания, поэтому назначайте её только мосту. Одних прав администратора для этой проверки недостаточно. Установка не переназначает группы существующих пользователей.

## Профили и агенты

В Settings → **OduPilot** настройте профили, агентов и серверы MCP. Профиль выбирает модель, ключ LiteLLM, тип рабочей папки, лимит сессий, доступность агентов и параметры разработчика. Общий базовый URL AI задаётся в настройках OduPilot. Назначьте профиль на странице безопасности пользователя.

Агент задаёт инструкции, правила инструментов и серверы MCP. Обычные разговоры можно запускать только с агентами, доступными профилю пользователя. Агенты только для MCP предоставляются через MCP, а не выбор чата. Необязательная сверка платежей требует соответствующих бухгалтерских и платёжных бизнес-модулей.

Для инструментов Odoo включите **MCP Active** и назначьте пользователю профиль MCP. Настройте сервер MCP с подстановкой токена сессии в заголовках. Каждая сессия получает подписанный токен, связанный с владельцем и профилем. Отзыв доступа и изменения политик проверяются при следующих вызовах. Личные API-ключи MCP независимы и должны учитывать сроки действия Odoo 17.

Профилям разработчика с рабочими деревьями нужны URL репозитория, базовая ветка, токен GitHub и настройки окружения. Задайте **Developers Profile** для меню разработчика и при необходимости **Responsible Developer**. Запрос, классифицированный как разработка, добавляет этого администратора в разговор и отправляет стойкое уведомление OduPilot.

## Диктовка

Диктовка использует учётные данные LiteLLM профиля и общий базовый URL AI. Модель расшифровки задаётся системным параметром `odupilot.transcription_model`; значение по умолчанию — `whisper-1`. Браузеру нужны безопасный контекст и разрешение микрофона. Ограничения: пять минут и 25 МиБ на запись. Аудио не сохраняется вложением. Расшифровка возвращает текст для редактирования перед отправкой запроса.

## Соединение и мониторинг

Мост опрашивает `/odupilot/bridge/poll` через обычный HTTP-адрес Odoo. Метод доступен только служебному пользователю; произвольные каналы шины выбрать нельзя. После пустого ответа мост ждёт одну секунду. Надёжная XML-RPC очередь команд остаётся источником истины. Маршрут длительного опроса Odoo 15 не используется. Для событий Discuss в браузере настройте стандартный WebSocket Odoo 17.

Сервер OduMCP опрашивает `/odumcp/v1/events` с короткоживущим билетом событий и ждёт одну секунду после пустого ответа. Запросы видят только частный канал владельца билета. Разворачивайте прилагаемую версию MCP-сервера вместе с этим модулем.

В **Monitoring** смотрите состояние моста/OpenCode и последние ошибки; для изучения работы используйте **Sessions**, **Commands** и журнал действий агентов. Мост переподключается к потоку событий OpenCode и загружает завершённые сообщения, подавляя дубликаты. После переподключения он также сверяет сессии. Команды доставляются по порядку и имеют идентификаторы идемпотентности.

## Восстановление и хранение

Задайте таймаут занятой сессии, сроки хранения событий и закрытых сессий в настройках OduPilot. Пятиминутная задача проверяет просроченные запросы. Она ставит остановку в очередь и может автоматически повторить запрос один раз, если инструменты не использовались. Иначе участник выбирает **Retry** или **Dismiss**. Запоздавший ответ завершает открытые записи восстановления и отменяет ненужные повторы.

Закрытие сессии отзывает её токен и ставит очистку рабочей папки в очередь. Политика хранения удаляет технические записи, сохраняя каналы и сообщения Discuss. Нулевой срок означает бессрочное хранение. Мост должен оставаться доступным для обработки команд очистки.

## Проверка

Запускайте тесты Odoo для `/odupilot,/odumcp`, тесты моста в `addons/odupilot/deploy` и тесты MCP-сервера в `addons/odumcp/deploy/odumcp_server`. Браузерные проверки используют изолированную базу Odoo. Рабочий провайдер, внешний репозиторий Git и окружение разработчика требуют отдельно настроенных служб; локальные имитации не проверяют их учётные данные.

## Совместимость с Odoo 17

Для новой установки на Odoo 17 используйте ветку `17.0`. Установите модуль из `addons` вместе с объявленными зависимостями. Эта ветка не предназначена для понижения версии существующей базы Odoo.
