# 2026-08-17

## Файлы рабочего каталога удаляются вместе с записью сессии

- Удаление технической записи AI-сессии теперь удаляет и её рабочий каталог со
  всеми вложениями и Markdown-версиями. Раньше это делало только закрытие чата,
  а удалённая запись оставляла файлы навсегда.
- Команда уборки переживает удалённую запись и несёт всё, что нужно мосту.
  Сессия, файлы которой уже удалены при закрытии, повторно не убирается.
- Ежедневная чистка удаляет такие завершённые команды уборки, когда они старше
  срока хранения событий.

## Читаемые вложенные документы

- Вложения Word, PowerPoint, Excel, OpenDocument, RTF, EPUB, CSV и PDF теперь
  преобразуются AnyDoc в Markdown и сохраняются рядом с оригиналом как
  `<file>.md`, поэтому AI читает содержимое, а не двоичный файл.
- В запросе перечисляются полученные преобразования, и AI получает указание
  пользоваться ими. Вложения других типов, например изображения, не меняются.
- Преобразование выполняет bridge, Bash для него не нужен, поэтому оно работает
  и в профилях с запрещённым Bash. Дополнительно команда `anydoc` доступна в
  контейнере OpenCode профилям, которым Bash разрешён.
- AnyDoc не распознаёт текст: отсканированный или состоящий только из
  изображений PDF не даёт Markdown и объявляется нечитаемым.

## Кликабельные упоминания записей

- Любое упоминание записи Odoo в ответе AI теперь открывает её форму:
  идентификатор в таблице результатов, а также задача по заголовку, стадия,
  проект или клиент, названные в обычном тексте.
- Ссылками становятся только записи, которые AI действительно прочитала через
  инструмент, поэтому ссылка не ведёт на угаданную запись. Количества и
  отфильтрованные списки вроде «55 задач в New» остаются обычным текстом.
- Адрес строит Odoo по собственному веб-адресу; AI лишь помечает, какой модели и
  какому идентификатору принадлежит упоминание.

## Видимые повторы провайдера

- Когда AI-провайдер повторяет запрос — например, после исчерпания лимита
  подписки — в беседе появляется уведомление с причиной, а не молчаливое
  **AI is responding…**.
- На каждую причину публикуется одно уведомление: одинаковые попытки молчат,
  другая причина публикует новое, а готовый ответ сбрасывает состояние.

## Минимальные права записи bridge

- RPC-методам bridge теперь нужна новая группа **OduPilot Bridge Service** вместо
  прав системного администратора, поэтому сервисной записи bridge больше не
  нужен доступ к чему-либо за пределами AI-чата.
- Системные администраторы больше не проходят проверку bridge неявно: группу
  нужно назначить осознанно.
- Обновление переводит запись с логином `odupilot-bridge`: она получает новую
  группу и теряет все остальные явно назначенные группы. Запись bridge с другим
  логином по-прежнему нужно перевести вручную, иначе она не сможет забирать
  команды, а её heartbeat будет отсутствовать.

## Доступ к созданию чата

- Внутренние пользователи теперь могут запускать **Новый чат с AI** без доступа
  к Настройкам. Серверному действию назначена та же группа внутренних
  пользователей, что и пункту меню в Обсуждениях.

## Читаемые ответы AI

- Добавлено полное отображение CommonMark в ответах AI: заголовки, списки,
  ссылки, блоки кода, зачёркивание и автоматическое распознавание URL.
- Таблицы Markdown преобразуются в адаптивные HTML-таблицы.
- Добавлена серверная очистка, удаляющая скрипты и опасные атрибуты до
  сохранения ответа AI как сообщения.
- Версия Markdown-рендерера зафиксирована в зависимостях production-образа
  Odoo.

## Команды bridge по событиям

- Ежесекундный XML-RPC polling команд заменён на сигналы Odoo longpolling.
- Надёжное получение команд, порядок FIFO, повторы и периодическая сверка
  сохранены в transactional outbox.
- Bus-уведомления не содержат payload команд, вложения или учётные данные.
- Корневой каталог OpenCode зафиксирован как `/workspace`; соответствующая
  настройка Odoo и переопределение через переменную окружения удалены.

## Восстановление после зависших запросов

- Добавлен настраиваемый таймаут и автоматический watchdog для сессий, которые
  остаются занятыми после сбоя модели, OpenCode или сети.
- Watchdog отменяет последующие запросы в очереди, записывает ошибку, уведомляет
  беседу и отправляет идемпотентное прерывание, чтобы сессия снова стала
  доступна без ручного изменения базы данных.
- Chaos-приёмка подтвердила backfill bridge без дублей. Падение процесса
  OpenCode во время активного provider stream устраняется watchdog.
- Прерванные запросы без активности инструментов или разрешений автоматически
  повторяются один раз. При активности инструментов и повторных сбоях в
  Обсуждениях появляется синхронизированная карточка **Повторить** / **Пропустить**.
- Поздний финальный backfill отменяет ещё ожидающие команды восстановления и
  не допускает повтор после уже полученного исходного ответа.
- Завершённые или вытесненные потоки ассистента теперь удаляют временное
  сообщение из Обсуждений, даже если задержанные события восстановления после
  сбоя приходят не по порядку.

## Устойчивый поток событий

- Одно некорректное событие больше не рвёт весь поток событий OpenCode. Текст с
  Unicode-разделителем строк разбивал одно событие надвое и обрывал соединение,
  из-за чего беседа оставалась на **AI is responding…** до тех пор, пока через
  полчаса её не освобождал watchdog занятых сессий.
- После каждого переподключения bridge сверяет занятые сессии с теми, которые
  OpenCode действительно выполняет, и сразу освобождает сессии с потерянным
  событием завершения, не дожидаясь watchdog.

## Карточки разрешений в Обсуждениях

- Добавлены встроенные карточки запросов разрешений OpenCode с действиями
  **Разрешить один раз**, **Всегда** и **Отклонить**.
- Ответы на разрешения доставляются через надёжный outbox и синхронизируются
  всем участникам беседы через Odoo longpolling.
- Отвеченные и истёкшие карточки остаются видимыми с итоговым статусом и
  пользователем; повторные нажатия и события не создают дубли ответов.

## Ответы AI в реальном времени

- Добавлено обновление текста ассистента в Обсуждениях через существующее
  longpolling-соединение Odoo.
- Во время генерации браузер обновляет одно экранированное временное сообщение,
  а затем заменяет его сохранённым Markdown-ответом без дублей.
- Прерывание, ошибка, восстановление watchdog и закрытие сессии удаляют
  устаревший live-вывод.

## Хранение и мониторинг

- Добавлена настраиваемая ежедневная очистка исходных событий аудита и
  технических записей закрытых сессий с сохранением каналов и сообщений
  Обсуждений.
- Добавлен отдельный dashboard состояния с heartbeat bridge/OpenCode,
  задержкой health-check, метриками очереди, зависших команд, ошибок и
  длительностей за 24 часа.
- Добавлена история команд с поиском, временем завершения и длительностью.

## Публикация среды разработки

- Добавлен автоматический bootstrap среды разработки через выбранный
  полноценный MCP-сервер с сохранением проверенного HTTPS URL в сессии чата.
- Добавлена защищённая команда публикации outbox: она отклоняет грязные или
  небезопасные worktree, отправляет созданную ветку и создаёт либо обновляет её
  pull request GitHub, не раскрывая PAT профиля модели.

## Состояние сессии в Обсуждениях

- Над каждой AI-беседой добавлена компактная панель инициализации, готовности,
  активной работы, ожидания разрешения, ошибки и закрытия сессии.
- Переходы состояния обновляются через существующее longpolling-соединение
  Odoo; Обсуждения не опрашивают модель сессии.
- При ошибке показывается ограниченная сводка, чтобы пользователь мог понять
  причину сбоя, не покидая беседу.
- AI-беседы теперь открываются только в Обсуждениях и больше не появляются как
  закреплённые окна чата поверх главного меню приложений.

## Надёжные ответы в среде разработки

- Устранено бесконечное повторение turn OpenCode после того, как модель уже
  вернула `finish=stop`: генерация ID сообщения оставлена OpenCode.
- Идемпотентность повторной доставки сохранена с помощью стабильного ID части
  prompt и проверки истории.

## Личная учётная запись Odoo MCP

- Пользователь может выбрать один личный API-ключ только для MCP как учётную
  запись по умолчанию для новых сессий OduPilot.
- Каждый чат получает отдельный временный MCP-ключ Odoo, доступный OpenCode как
  `ODOO_API_KEY` и отзываемый при закрытии чата.
- В заголовке удалённого MCP можно использовать
  `Bearer {env:ODOO_API_KEY}`, не сохраняя ключ пользователя в записи сервера
  MCP; JSON-конфигурация OpenCode не поддерживает `${ODOO_API_KEY}`.

## Учётные данные LiteLLM в профиле

- Назначение профиля OduPilot теперь находится на вкладке пользователя
  **Безопасность учётной записи**, а не в **Настройках**.
- В каждом профиле появилась доступная только для чтения вкладка
  **Пользователи** со всеми активными и архивными назначенными пользователями,
  их логинами, компаниями и признаком активности.
- API-ключ LiteLLM задаётся один раз в профиле OduPilot и используется всеми
  пользователями, которым назначен этот профиль.
- Существующие пользовательские ключи переносятся в профили; если у назначенных
  одному профилю пользователей были разные ключи, профиль разделяется.
