# Администрирование книги документации

Книга работает с файлами. Руководства модулей и архив изменений не хранят
документацию в базе данных и не переводятся во время обработки запроса. В базе
лежат только персональные отметки прочтения архива изменений и документы,
вручную положенные на полку **Пособия**.

## Управление доступом

Руководство пользователя, Пособия и Изменения доступны внутренним
пользователям. Руководство администратора ограничено группой Настроек
(`base.group_system`) и в меню, и на серверном endpoint. На полке Пособий у
внутренних пользователей только доступ на чтение; добавление и удаление
документов требует группы Настроек, и это проверяет ACL, а не скрытие кнопок.

Отметки прочтения хранятся в `odubook.change.read` (одна строка на
пользователя, модуль и дату). Внутренние пользователи могут читать, создавать и
изменять строки, но не удалять их, а правило записи ограничивает любую операцию
их собственными строками.

## Непрочитанные записи

Запись — это один модуль за одну дату. Она отмечается прочитанной, как только её
текст отдан читателю; **Отметить всё прочитанным** отмечает всё, что сейчас
лежит на диске.

Два порога заданы константами в `models/odubook.py`:

| Константа | По умолчанию | Значение |
|---|---|---|
| `NEW_ENTRY_DAYS` | 3 | как долго запись несёт зелёный лейбл **Новое** |
| `UNREAD_HORIZON_DAYS` | 90 | записи старше не считаются непрочитанными |

Горизонт не даёт залитому историческому архиву превратить каждый список в
жирный текст и точно так же работает для новых сотрудников, без миграции
данных. Удаление отметок (например, чтобы заново показать архив одному
пользователю) — обычное удаление строк `odubook.change.read`.

## Полка «Пособия»

**Пособия** хранят документы, которые не лежат рядом с кодом модуля. Одна
запись `odubook.manual` — один документ: `name` — заголовок в сайдбаре, а
`sequence` задаёт порядок на полке. Файлы живут в `odubook.manual.file` — по
строке на язык, у каждой своё `file_name`.

Документ добавляется кнопкой **Добавить документ** под полкой: выберите файл,
поправьте предложенный заголовок, выберите язык и подтвердите. Пунктирная
кнопка языка над открытым документом загружает недостающий перевод; повторная
загрузка того же языка заменяет файл, а не добавляет второй.

При включённых демоданных модуль добавляет пример документа: **Sales Cube — sales management model** —
интерактивный артефакт модели `veles_sales_cube` на английском, польском и
русском. Он создаётся один раз при установке с `noupdate="1"`, поэтому правка
или удаление в UI переживают апгрейд; новая версия артефакта загружается на
полку вручную.

Читатель получает версию своего языка, затем английскую, затем единственную на
полке — поэтому документ, вложенный на одном языке, остаётся читаемым для всех.
**Удалить** снимает открытый перевод, а последний уходит вместе со всем
документом.

Как показывать документ, решает расширение файла, а не MIME-тип, присланный
браузером:

| Расширение | Показывается как |
|---|---|
| `md`, `markdown` | отрендеренный Markdown, как руководство |
| `txt`, `log`, `csv` | экранированный обычный текст |
| `html`, `htm` | сам документ, в песочнице фрейма |
| `pdf` | просмотрщик PDF браузера |
| `png`, `jpg`, `jpeg`, `gif`, `svg`, `webp`, `bmp` | изображение |
| всё остальное | только ссылка на скачивание |

Вложенный документ HTML отдаётся с `Content-Security-Policy: sandbox` и
показывается в `iframe` без `allow-same-origin`, поэтому его скрипты работают в
собственном origin и не достают до сессии читателя Odoo. И всё же полка
намеренно доступна на запись администратору: относитесь к вложенному артефакту
как к коду, за который вы ручаетесь.

Файл не может быть больше 25 МБ, а на сервере рендерится только текстовый
документ меньше 4 МБ; более крупный или не-UTF-8 текстовый файл откатывается к
ссылке на скачивание.

## Добавление документации к модулю

Модуль подключается к Книге добавлением файлов в каталог `doc/`:

| Файл | Назначение |
|---|---|
| `user_guide.md` | Инструкции для бизнес-пользователей |
| `admin_guide.md` | Настройки и привилегированные операции |
| `tech_spec.md` | Технический контракт; не показывается в Книге |
| `changes/YYYY-MM-DD.md` | Изменения за день, написанные на исходном языке |

Показываются только установленные модули. Префикс технического имени не нужен.

## Языки документации

Исходный язык — английский. Настроенные целевые языки: польский и русский.
Зеркала руководств находятся в
`doc/i18n/<lang>/user_guide.md` и `doc/i18n/<lang>/admin_guide.md`, а записи
летописи зеркалируются по одному файлу в
`doc/i18n/<lang>/changes/YYYY-MM-DD.md`.

Руководства и каждая запись летописи поддерживаются на всех трёх языках:
английском, польском и русском.

Каждое зеркало начинается с SHA-маркера, указывающего точную версию исходника,
с которой выполнен перевод. Поддерживайте переводы с помощью skill
`odubook-i18n` и проверяйте командой:

```bash
python3 .claude/skills/odubook-i18n/scripts/check_docs.py
```

Во время работы используется короткий код языка пользователя Odoo (`pl_PL` →
`pl`), а при отсутствии документа выполняется возврат к английскому исходнику —
одинаково для руководства и для записи летописи. Какие даты есть в архиве,
всегда решают английские источники, поэтому недостающее или лишнее зеркало не
может добавить или скрыть запись. `tech_spec.md` остаётся только на исходном
языке.

Кнопки языков, которые читатель видит над руководством или записью летописи,
нигде не настраиваются: это найденные на диске зеркала. Язык появляется, как
только хотя бы один установленный модуль несёт `doc/i18n/<lang>/` с этим
документом, и исчезает с последним таким зеркалом; английский предлагается
всегда. Поэтому наборы кнопок могут различаться между разделами, если для них
настроены разные зеркала, а язык, запрошенный в обход интерфейса, сервер
игнорирует. Чтобы кнопка появилась, достаточно добавить целевой язык в
`LANG.local.md` и перевести настроенные документы; никакой записи настроек для
этого не нужно.

Чтение на другом языке ничего не записывает: выбор живёт только в открытом
представлении.

## Пункт «Язык» в меню пользователя

**Язык** — между **Горячими клавишами** и **Моим профилем** под именем самого
пользователя — меняет язык всего интерфейса. Это противоположность кнопкам
Книги: пункт пишет `lang` в собственную запись `res.users` читателя и
перезагружает страницу, потому что уже собранный веб-клиент не может подменить
свои переводы сам.

Пользоваться пунктом вправе каждый пользователь без дополнительных прав: `lang`
— одно из полей Odoo, которые пользователь может писать себе сам, а диалог не
пишет ни других полей, ни чужих записей. Группой пункт не закрыт, и настраивать
для него нечего.

Диалог перечисляет **активные** записи `res.lang`, поэтому язык появляется в нём
только после установки через **Настройки → Переводы → Языки**. Установка языка
сама по себе не переводит кастомные модули — модуль переведён на него, только
если несёт `i18n/<lang>.po`. Кнопки языков самой Книги от всего этого не
зависят: они читают Markdown-зеркала с диска и работают для языка, вообще не
установленного в базе.

## Изоляция ошибок

Нечитаемые, некорректные UTF-8 или слишком большие файлы документации
пропускаются и записываются в лог, не нарушая работу всей Книги.
Сформированный HTML кэшируется в каждом worker и обновляется при изменении
времени модификации файла.

## Совместимость с Odoo 17

Для новой установки на Odoo 17 используйте ветку `17.0`. Установите модуль из `addons` вместе с объявленными зависимостями. Эта ветка не предназначена для понижения версии существующей базы Odoo.
